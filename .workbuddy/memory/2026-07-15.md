## 22:50+ — 修复 Unicode 花色符号渲染问题 + 启动游戏

### 问题诊断
- 截图显示红桃(♥)、梅花(♣)等 Unicode 符号显示为方块替代符 □
- 根因：`pygame.font.SysFont("georgia,cambria,palatino,serif")` 在 Windows 上字体回退链不确定，Georgia/Cambria 可能不支持完整 Unicode 扑克牌花色 (U+2660-U+2666)

### 测试验证
| 字体 | ♥ | ♦ | ♣ | ♠ |
|------|---|---|---|---|
| Cambria | 13px ✅ | 14px ✅ | 11px ✅ | 11px ✅ |
| 微软雅黑 (msyh.ttc) | 14px ✅ | 14px ✅ | 14px ✅ | 14px ✅ |
| Segoe UI | 14px ✅ | 14px ✅ | 14px ✅ | 14px ✅ |
| Times New Roman | 12px ✅ | 10px ⚠ | 13px ✅ | 11px ✅ |

**结论**：Segoe UI / 微软雅黑都有完整的 Unicode 扑克牌花色支持。Cambria 也支持但 ♠ 略窄。Times 的 ♦ 只有 10px，说明字形偏窄。

### 修复方案
将 `ui_manager.py` 所有字体加载从 `pygame.font.SysFont("georgia,...")` 
改为 `pygame.font.Font("C:/Windows/Fonts/msyh.ttc", size)` — 直接指定文件路径跳过字体名解析的 fallback 陷阱。

**为什么选微软雅黑？**
- 内置完整 Unicode 扑克牌花色 (U+2660-U+2667)
- 是 Windows 10/11 标配字体（所有用户系统都有）
- 中英文混合渲染效果优秀
- 直接通过 `pygame.font.Font()` 使用可避免 SysFont 的字体系列匹配问题

### 代码变更
- `ui_manager.py`: +20 -14 行
  - 字体回退逻辑简化为一行 `_unicode_font = "C:/Windows/Fonts/msyh.ttc"`
  - 所有 card fonts 改用 `pygame.font.Font(_unicode_font, size)`
  - HUD/UI 文字仍用 SysFont（microsoftyahei 已在 sans 回退链中）
